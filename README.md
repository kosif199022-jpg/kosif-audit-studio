# KOSIF Audit Studio

## الإيجنت والنشر مع الحفاظ على النسخة الأصلية

هذا الفرع يعتمد النسخة المطابقة للرابط الذي حدده المستخدم، ويحافظ على الثيمات
الثلاثة ووظائفها، ويضيف «الإيجنت وخطة العمل» من القائمة: محادثة محلية، خطط
ومتابعة مهام، تسعة تخصصات للتحدي، مرصد مراجع، ومذكرات قابلة للتحرير.
راجع [تقرير اعتماد الأساس والنشر](docs/CLOUDFLARE_BASELINE_ADOPTION.md).
للبناء على Cloudflare Pages: `npm run build:cloudflare` والمخرج `dist/client`.

يعتمد التطوير الحالي [عقد التنفيذ المصحح v1.1](docs/KOSIF_EXECUTION_CONTRACT_V1_1.md):
مبالغ `bigint`، رسم إسناد قابل للنقر، رأي ISA 705 مشتق، مخطط D1 متعدد
المستأجرين، وواجهات API ترفض افتراضيًا.

## Cloud Foundation v1

أضيف أساس سحابي تدريجي لا يغير الثيمات أو محركات التدقيق الحالية:

- `GET /api/session` لقراءة الهوية والدور والصلاحيات بعد التحقق الخادمي.
- `GET /api/engagements` لقائمة ارتباطات المستأجر الحالية.
- `GET /api/engagements/:id/workspace` لقراءة أحدث مراجعة وصفية محفوظة.
- `PUT /api/engagements/:id/workspace` لحفظ مراجعة جديدة append-only مع SHA-256 وتعارض متفائل عبر `base_revision`.
- جدول D1 جديد `engagement_workspace_revisions` مع عزل مركب للمستأجر/الارتباط، ومنع التعديل والحذف ومنع الكتابة بعد الأرشفة.
- وحدة `src/cloud-sync.js` للنقل نفسه، وكشف تعارض `409`، وAutosave يجمع التغييرات السريعة ولا يستبدل حالة خادم أحدث بصمت.

هذه المرحلة **لا تنقل** صفوف ميزان المراجعة الخام أو ملفات الأدلة إلى JSON السحابي، ولا تخزن مفاتيح مزودين فيه. واجهة React الحالية لا تزال تستخدم التخزين المحلي كمسار التشغيل الافتراضي إلى أن يكتمل ربط هوية سحابية موثقة بالواجهة.

خلف OpenAI Sites تبقى ترويسة الهوية الخادمية الحالية هي مسار المصادقة الموثوق. أما نطاق Cloudflare المباشر فيحذف تلك الترويسة ويرفض API غير الموثق؛ لا يُقبل بريد يرسله العميل كترويسة بديلة. يلزم Cloudflare Access/OIDC موثّق قبل تفعيل الحفظ السحابي للمستخدمين على `pages.dev`.

راجع [تصميم Cloud Foundation v1](docs/superpowers/specs/2026-09-05-cloud-foundation-v1-design.md) و[خطة التنفيذ](docs/superpowers/plans/2026-09-05-cloud-foundation-v1.md).

تطبيق عربي مستقل لإدارة مسار المراجعة من قبول الارتباط وميزان المراجعة إلى ربط المعايير والتحليلات والأدلة والمخاطر والتقرير المحكوم.

## التشغيل المحلي

```bash
npm install
npm run dev
```

للاستيراد والتشغيل في Google AI Studio راجع [AI_STUDIO.md](./AI_STUDIO.md). ولا يحتاج التطبيق في وضعه الحالي إلى مفتاح API.

## التحقق والبناء

```bash
npm test
npm run test:sites
npm run build:ai
```

ينشئ أمر البناء حزمة Sites داخل `dist/`، وتدعم طبقة Worker المسارين `/` و`/audit/` مع SPA fallback صحيح بدل صفحة 404.

## ما يتضمنه التطبيق

- واجهة RTL متجاوبة للجوال والتابلت واللابتوب.
- هوية KOSIF بنفسجية مستوحاة من v3، مع مظهر داكن مستوحى من v2 ومظهر تراثي أخضر قابل للتبديل والحفظ محليًا.
- وضع عرض تنفيذي يخفي شريط الأدوات الجانبي من دون تغيير البيانات أو القرارات.
- ملف ارتباط تجريبي شامل وحتمي من 5,000 حساب متوازن يغطي 20 مجالًا وكل نتائج التطبيق.
- وحدات نقدية صغرى صحيحة بالريال السعودي وتحقق آلي من التوازن الدقيق.
- بحث وتصفية وتصفح وتصدير CSV.
- 20 مجالًا محاسبيًا و58 موضعًا معياريًا تشغيليًا (32 محاسبيًا و26 مراجعة) من IFRS/IAS وISA ومتطلبات SOCPA، مرتبطة بالتأكيدات والمخاطر والإجراءات والأدلة.
- مركز معايير مع حالات اقتراح ومراجعة بشرية وقائمة استثناءات قابلة للتتبع.
- مختبر تطبيقي يضم 14 حالة مهنية مترابطة؛ يحوّل الواقعة إلى أسئلة معالجة ومخاطر وتأكيدات وإجراءات وأدلة ومخرجات ورقة عمل، ويربطها بالحسابات الفعلية والتعرض المالي في الميزان.
- 8 أشجار قرار مهنية تشمل IFRS 15 وIFRS 16 وIFRS 19 وIFRS 9 وIAS 19، إضافة إلى IAS 8 ونطاق التوحيد وفق IFRS 10 والانتقال إلى IFRS 18 ومقاييس الأداء المحددة من الإدارة.
- 7 نماذج قياس قابلة لإعادة الأداء لـIAS 2 وIFRS 9 وIAS 36 وIAS 12 وIAS 33 وIFRS 3 وIAS 21، مع استخدام التعرض المرتبط كنقطة بداية قابلة للتعديل من دون إنشاء قيد آلي.
- قائمة جاهزية لدورة المحاسبة والإقفال من 12 محورًا، وخريطة انتقال IFRS 18 تفصل التصنيف وMPMs والتجميع والسريان، وحزمة تطبيقية قابلة للتنزيل.
- تحليلات نسب وسيولة ورفع وهوامش وتركيز واختبار الرقم الأول.
- 20 جولة مراجعة و20 طلب دليل و20 ملاحظة مترابطة، مع جولة متابعة إضافية لا تبدأ إلا بقرار بشري.
- رفع PDF والصور وExcel وCSV وTXT وDOCX للأدلة، وحساب SHA-256 من البايتات محليًا، وحفظ المحتوى في IndexedDB داخل الجهاز لإعادة فحص الحجم والبصمة عند الاعتماد والتصدير؛ لا يُرسل الملف إلى خادم ولا يدخل محتواه في JSON.
- 12 بوابة إصدار تفشل عند نقص العلاقات أو البصمات أو الاستنتاجات أو فصل المهام أو التسلسل الزمني، وتمنع اعتماد التقرير قبل اكتمال المتطلبات والقرار البشري.
- حفظ محلي لبيانات الحالة الوصفية في `localStorage` وبايتات الأدلة المرفوعة في IndexedDB، مع إمكانية إعادة بيانات العرض. الميزان المستورد يظل خاصًا بالجلسة ويجب تنزيل لقطته قبل إعادة التحميل. أصبح عقد الحفظ الوصفي السحابي متاحًا في Cloud Foundation v1 لكنه غير مربوط افتراضيًا بالواجهة حتى اكتمال المصادقة السحابية الموثقة.
- استيراد XLSX/XLS/CSV/TSV/TXT عبر منطقة تحضير تمنع الالتزام قبل فحص الأعمدة والتكرارات والإشارات والتوازن الدقيق. اعتماد مجموعة جديدة يبطل نتائج المجموعة السابقة بدل خلطها.
- مسار مستخدم من سبع خطوات، و20 جولة مترابطة، وعينة مخاطر حتمية، وسلسلة حساب ← معيار ← تأكيد ← إجراء ← دليل ← نتيجة.
- حالة عرض مكتملة تتضمن 26 قرار ربط بشري، وجميع الأدلة والملاحظات والتسويات، وجولتي مجلس، وقفل الفترة، ورأيًا غير معدل معتمدًا لأغراض العرض فقط.
- سلسلة بصمات SHA-256 لقيود اختبارية، وتسويات بنكية بحالات مطابقة واستثناء، وقفل فترة بقاعدة شخصين.
- مجلس تحليلي من أربعة مقاعد استشارية مع قرار بشري منفصل ومحفوظ؛ لا يختار نوع الرأي ولا يعتمد التقرير.
- مركز حزم عمل يوفّر تقرير PDF عربيًا من 15 صفحة ومصنف Excel من 12 ورقة يتضمن 11 فحص مصالحة لسيناريو العرض v7 ذي 5,000 حساب، إضافة إلى النماذج التطبيقية السبعة ودورة الإقفال وIFRS 18 وجرد مصادر التعلّم، وCSV ولقطة JSON مؤقتة، وطباعة وJSON محكومين ببوابات الإكمال والاعتماد البشري.
- مركز نتائج موحد يعرض النسب وكل مجالات التحليل والمعايير والعينة والقيود ومسارات الأدلة والجولات والملاحظات والتسويات وبوابات الإصدار.
- تنزيل لقطة JSON مؤقتة كاملة للحالة الملتزم بها وكل الحسابات، وتنزيل CSV دقيق للميزان الحالي مع تحييد صيغ الجداول؛ لا تشمل اللقطة منطقة التحضير أو محتوى المرفقات ولا تمثل سجلًا موقعًا.
- سجل صريح لمحركات التحليل: KOSIF المحلي نشط، والمزودون الخارجيون غير مهيئين ما لم يوجد تكامل خادمي آمن.

راجع [مراجعة قدرات المستودعات](./docs/REPOSITORY_CAPABILITY_REVIEW.md) و[سجل الاستفادة من المرفق](./docs/ATTACHMENT_ADOPTION.md) و[مراجعة قوائم YouTube وتبنّي القدرات](./docs/YOUTUBE_CAPABILITY_ADOPTION.md) لمعرفة ما تم دمجه وما استُبعد وحدود البيانات. تغطي الحزمة 7 خطوات إرشادية و10 مراحل تشغيل و12 بوابة إصدار و15 قسم تنقّل. البيانات المضمّنة تجريبية، ومسار الواجهة التشغيلي الافتراضي ما زال محليًا، بينما أصبح عقد حفظ وصفي سحابي خادمي متاحًا خلف المصادقة الموثقة. ملخصات المعايير ليست النصوص الرسمية الكاملة، والتطبيق أداة مساعدة لا تستبدل الحكم المهني أو اعتماد مراجع مرخّص.
