# KOSIF Audit Studio — عقد التنفيذ المصحح v1.1

تُعتمد مواصفة المستخدم v1.0 مرجعًا وظيفيًا. هذه الوثيقة تسجل فقط التصحيحات
اللازمة كي تصبح قابلة للفرض على Cloudflare D1 وWorkers من دون ادعاءات أمان
لا يحققها التنفيذ.

## قرارات ملزمة

1. **المال عبر D1:** يُخزن كنص عشري canonical ويعبر حدود Worker كنص، ثم
   يتحول إلى `bigint`. السبب أن نقل SQLite `INTEGER` إلى JavaScript لا يضمن
   الدقة بعد `2^53-1`.
2. **هوية النتائج:** `figure_id` و`derivation_id` و`run_id` معرّفات مبنية على
   محتوى المدخلات وإصدار القواعد، وليست ULID زمنية. وقت التقييم مدخل صريح لكنه
   لا يغير هوية النتيجة إذا لم يغير الحساب.
3. **الإسناد:** `derivation_inputs` علاقة مطبّعة؛ لا تعتمد سلسلة التتبع على
   `inputs_json` غير القابل للتحقق.
4. **الرأي:** لا يُخزن نوع قابل للكتابة. D1 يولده بعمود
   `GENERATED ALWAYS AS`، والواجهة تستدعي `isa705Decide()` فقط.
5. **الماضي:** القرارات المهنية نسخ إلحاقية (`mapping_sets`,
   `materiality_versions`, `finding_dispositions`, `opinion_assessments`,
   `ai_reviews`) بدل تعديل صف تاريخي.
6. **العزل:** كل ارتباط يملك `tenant_id`، وكل API في جدول مسارات بصلاحية
   صريحة. العلاقات التابعة تستخدم مفاتيح أجنبية مركبة
   `(engagement_id, parent_id)`، لا معرّف الأب وحده. المسار غير المعلن يرفض
   بـ403، والمعلن بلا هوية يرفض بـ401، والدور يُقرأ من `tenant_members` قبل
   تنفيذ الإذن.
7. **ميزان المراجعة والدفتر:** سطور ميزان المراجعة ممثلة مستقلًا عن سطور دفتر
   الأستاذ. لا يُجمع المصدران في قائمة واحدة بلا مصالحة تمنع العد المزدوج.
8. **المرحلة الثانية:** لا تُنشأ جداول تخمينية بلا عقد حقول واختبارات؛ تُضاف
   بترحيلات لاحقة مستقلة بعد اجتياز M6.

## حالة التنفيذ

| المجال | الحالة الحالية | البوابة |
|---|---|---|
| مخطط D1 متعدد المستأجرين | منفذ بترحيل Drizzle أولي | تطبيق SQL ناجح على SQLite |
| عزل العلاقات | composite FKs لكل علاقة مملوكة للارتباط | اختبارات cross-engagement فعلية |
| سجل النزاهة | append-only + منع fork + تحقق SHA-256 + كتابة ملاحظات بعد الأرشفة | A6 |
| قفل الأرشفة | 23 جدولًا مملوكًا للارتباط محمية عند الإدراج، والتاريخ append-only | مصفوفة 76 trigger |
| المال والأهمية | `bigint` + basis points + CHECK canonical في D1 + حارس نوع | R1 + اختبارات قاعدة البيانات |
| القوائم والإسناد | تشغيل حتمي وعرض trace بالنقر | A1, A2 |
| ISA 240 | عشرة اختبارات صافية بإصدار ومعلمات | اختبارات المحرك |
| ISA 705 | نوع مشتق؛ لا مقاصة كمية؛ جوهرية قيد النطاق والانتشار حكمان بشريان مبرران | R4, A4 |
| عقد ادعاء الذكاء الاصطناعي | رفض الرقم غير المسند أو المخالف أو لغة الرأي | A5 |
| التطبيع العربي | أرقام عربية/فارسية وهللات بلا `parseFloat` | A8 |
| مصادقة وتفويض API | هوية Sites الخادمية + deny-by-default + مصفوفة RBAC فعلية | R2, I7 |

| حفظ الملفات الأصلية في R2 | مخطط المصدر جاهز؛ مسار الاستيعاب الخادمي مؤجل إلى M2 | غير مكتمل |
| DOCX حقيقي | التنزيلات المحلية الثلاثة OOXML حقيقية ومختبرة؛ مسار التقرير الخادمي المحكوم مؤجل | R5 يمر محليًا؛ مسار الخادم غير مكتمل |

## حسم القرارات المفتوحة

- `isPervasive`: تقييم كلي للرأي، مع تبرير بشري ومراجع للبنود المتأثرة.
- الأرصدة الافتتاحية غير المدققة: نتيجة ISA 510 ثم قرار بشري بعد الإجراءات
  البديلة؛ لا تتحول تلقائيًا إلى قيد نطاق.
- الإجازات: تقويم سعودي محفوظ داخل إصدار القواعد، بلا جلب شبكي وقت التشغيل.
- الجوهرية النوعية: ضمن المرحلة الأولى، بفئة وسبب ومراجع بشري؛
  `isMaterial = quantitative OR approvedQualitative`، والأساس الكمي هو الأكبر
  من مجموع المبالغات ومجموع التخفيضات وأكبر بند منفرد، من دون مقاصة بين
  الاتجاهين. الصافي قيمة عرض لا بوابة قرار.

## حد الترحيل

بيانات العرض الحالية هي ميزان مراجعة اصطناعي. شاشة الإسناد تنشئ عقدة سطر
حتمية لكل صف لإثبات عمل الرسم، وتوسمها `trial_balance_adapter`. لا تُعامل هذه
العقد كدليل عميل. عند M2 يعاد الاستيعاب من الملف الخام وتستبدل بالعقد الأصلية
من `trial_balance_lines` و`journal_lines`.
