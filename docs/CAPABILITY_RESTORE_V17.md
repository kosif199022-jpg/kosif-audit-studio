# مراجعة واستعادة قدرات KOSIF — الإصدار 17

## النطاق والمصادر

تمت مراجعة النوافذ العامة في المصدرين التاليين ومقارنتها بالمصدر الحالي، مع
فحص المستودعات المرتبطة بدل نسخ واجهات Worker المبنية فقط:

- `mahmoud-eldesouky.kosif199022.workers.dev/audit/`
- `kosif-stable-capabilities-v2.kosif199022.workers.dev`
- `kosif199022-jpg/mahmoud1990` — الفرع الرئيسي والمرجع التاريخي
  `a1990-v35-import`.
- `kosif199022-jpg/Acc` — مصدر عقد قدرات v2/v3 عند المرجع
  `45a3ab9f...`.
- `kosif199022-jpg/kosif-audit-studio` — وجهة GitHub؛ كان فرعه الرئيسي نسخة
  ثابتة أقدم، ولذلك تتم المزامنة في فرع مراجعة مستقل ولا يُستبدل `main`
  مباشرة.

المبدأ: تستعاد القدرة إذا كان مصدر بياناتها واضحًا، وحسابها قابلًا لإعادة
الأداء، ولا تتجاوز سلطة المراجع أو تضع سرًا في المتصفح. القدرة التي لا تحقق
ذلك تسجل ولا تنسخ كما هي.

## القدرات المحفوظة من دون تراجع

- 5,000 حساب متوازن بالهللة، 20 جولة، 20 نتيجة، وطلبات PBC مترابطة.
- رسم إسناد حتمي، عشرة اختبارات ISA 240، وقرار ISA 705 مشتق.
- مخطط D1 متعدد المستأجرين، علاقات مركبة، سجل إلحاقي، وحراس الأرشفة.
- مركز معايير وأدوات SOCPA/IFRS، مختبر تطبيقي، مجلس مهني، مخرجات وتقارير،
  لوحة أوامر، وصول، وثيمات الواجهة الحالية.
- XLSX من 12 ورقة، CSV وJSON محكومان، ومخرجات الطباعة العربية.

## ما لم يُنسخ عمدًا

| النمط في التطبيقات القديمة | القرار |
| --- | --- |
| إدخال مفاتيح Gemini أو عنوان Worker في المتصفح | مرفوض؛ أي مزود خارجي يحتاج registry خادميًا وأسرارًا لا تصل للعميل |
| اختيار نوع الرأي مباشرة أو إصدار تقرير قبل البوابات | مرفوض؛ النوع مشتق والإصدار يتطلب الاعتماد البشري |
| PBC يساوي صفرًا رغم وجود طلبات أو ملفات بلا بصمة | مرفوض؛ البوابة الآن من المصدر المحكوم نفسه |
| ملفات HTML باسم `.doc` | أزيلت؛ كل تنزيل Word أصبح OOXML حقيقيًا |
| أرقام أو نسب أو رسوم من مجموعة مرجعية أخرى | مرفوض؛ لا قدرة تعد ناجحة ما لم تتصالح مع مجموعة الجلسة |
| نسخ 118 مسار API قديمًا بلا تفويض وعقد بيانات | مؤجل إلى ترحيلات خادمية صغيرة مع RBAC واختبارات لكل مسار |
| جلب URL يقدمه المستخدم أو عرض نصوص معايير محمية | مرفوض أمنيًا وحقوقيًا |

## الأعمال الخادمية المتبقية

القدرات التالية ليست مناسبة لاستعادة واجهية صامتة، ولم يُدّع اكتمالها:

1. استيعاب الملف الخام إلى R2 مع تشفير tenant-scoped والاحتفاظ بالأصل.
2. تطبيق بقية مسارات API المهنية فوق D1/R2 ومصفوفة RBAC الحالية.
3. مزودات ERP/AI بخادم same-origin وإدارة أسرار، لا اتصالات يحددها العميل.
4. توليد DOCX/PDF محكوم من مسار التقرير الخادمي عند اكتمال طبقة الملفات؛
   التنزيلات المحلية الحالية OOXML صحيحة لكنها لا تمثل تقريرًا موقعًا.

## بوابة القبول

- البناء الإنتاجي وتهيئة Sites يجب أن ينجحا.
- جميع اختبارات المشروع، بما فيها R1–R6 وA1–A8 واختبارات OOXML الثلاثة،
  يجب أن تمر قبل المزامنة أو النشر.
- تتم المزامنة إلى فرع GitHub مستقل ثم Pull Request؛ لا تحديث قسري لـ`main`.
