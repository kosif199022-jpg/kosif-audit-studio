## الإضافات

- نقل وظائف الإيجنت المحلي من إصدار KOSIF 4 إلى طبقة متوافقة مع بيانات React الحالية.
- خطط مخاطر وإكمال، مسؤول وموعد ومبرر لكل مهمة، سجل انتقالات وآخر خمس خطط.
- محادثة مستندة إلى الملف مع مصادر وبصمة تغير؛ إملاء وقراءة اختياريان.
- مسودات مذكرات قابلة للتحرير والتنزيل تحتفظ ببصمة مصدرها الأصلي، حتى بعد حفظها لاحقًا.
- مرصد مصادر رسمية مع تواريخ السريان بحسب بداية الفترة ومحفوظات المراجع.
- تسعة تخصصات لأسئلة التحدي، مع إبقاء المجلس الحالي وقراراته البشرية وبواباته.
- العمل دون اتصال لأصول التطبيق العامة فقط؛ لا تخزين مؤقت لواجهات API أو البيانات أو روابط تحمل استعلامات.

الثيمات الثلاثة وملفات CSS الأصلية وصور الواجهة والخطوط وبوابات التقرير
ومحرك الحسابات والملفات المرفقة محفوظة. الإضافات تستخدم متغيرات الثيم الحالية.
حالة الإيجنت ضمن حالة الارتباط المحلية وتدخل في تصدير JSON الحالي؛ استعادة
JSON تبقى وفق عقد المصدر الأصلي: بيانات خام فقط، دون إعادة اعتماد قرارات قديمة.

## Cloud Foundation v1

أضيفت طبقة خادمية انتقالية فوق الأساس نفسه من دون تغيير الهوية البصرية:

- جلسة وصلاحيات صريحة عبر `GET /api/session`.
- قائمة ارتباطات مستأجر عبر `GET /api/engagements`.
- قراءة وحفظ حالة وصفية إصدارية عبر `GET/PUT /api/engagements/:id/workspace`.
- جدول D1 `engagement_workspace_revisions` بعزل مركب `(tenant_id, engagement_id)`، وتاريخ append-only، ومنع كتابة بعد أرشفة الارتباط.
- حفظ متفائل باستخدام `base_revision`; التعارض يعيد `409` بدل الكتابة فوق نسخة أحدث.
- SHA-256 لكل مراجعة وسجل `workspace.saved` يحفظ رقم المراجعة والبصمة فقط، لا يكرر الحالة كاملة في سجل التدقيق.
- فلتر خادمي يسمح بحالة وصفية محدودة الحجم ويمنع مفاتيح البيانات الخام والبايتات والأسرار.
- وحدة متصفح `src/cloud-sync.js` لعقد النقل وكشف التعارض وAutosave المتراكم.

هذه الطبقة لا تجعل نطاق Cloudflare المباشر موثقًا تلقائيًا. غلاف Cloudflare ما زال يحذف ترويسة هوية Sites من طلبات الإنترنت؛ لذلك ترفض API على `pages.dev` الطلب غير الموثق. لا يُقبل بريد يرسله العميل كترويسة بديلة. يلزم Cloudflare Access/OIDC مع تحقق تشفيري قبل ربط Autosave السحابي بواجهة الإنتاج على النطاق المباشر.

كذلك لا تنقل هذه المرحلة صفوف ميزان المراجعة الخام أو دفتر الأستاذ أو بايتات الأدلة إلى D1. نقل الملفات الأصلية يبقى مسار R2 مستقلًا لاحقًا، والواجهة الحالية تبقى محلية افتراضيًا إلى أن تكتمل هوية السحابة وربط المزامنة.

راجع `docs/superpowers/specs/2026-09-05-cloud-foundation-v1-design.md` و`docs/superpowers/plans/2026-09-05-cloud-foundation-v1.md`.

## النشر

فرع النشر: `codex/preserve-theme-cloudflare`.

أمر Cloudflare Pages: `npm run build:cloudflare`.
مجلد النشر: `dist/client`.

يمر النشر بالبناء والاختبارات قبل إعداد Worker. تستخدم حزمة Cloudflare `worker/index.js`
وتضيف غلافًا يزيل ترويسة هوية Sites من طلبات الإنترنت، لأن هوية تلك الترويسة
موثوقة فقط خلف Sites. واجهات API ترفض الطلبات غير الموثقة. وظائف الواجهة المحلية
تعمل كما كانت؛ هذه العملية لا تنقل قاعدة بيانات أو مفاتيح مزودين من حساب Sites
الأصلي. بيانات المستخدم المحلية لا تنتقل بين النطاقات تلقائيًا؛ يمكن نقل الميزان
عبر لقطة JSON الحالية، وإرفاق الأدلة محليًا في النطاق الجديد عند الحاجة.

ملف `.openai/hosting.json` محفوظ للتوافق مع المشروع الأصلي؛ لم ينشر هذا التغيير
فوق رابط Sites الأصلي. فرع `main` مختلف البنية ولا يستخدم تلقائيًا كأساس لهذا النشر.

## التحقق

الأساس اجتاز 174 اختبارًا، ونسخة اعتماد Cloudflare السابقة اجتازت 180 اختبارًا.
Cloud Foundation v1 يضيف اختبارات مستقلة لمسارات API، وRBAC، وعزل D1، والحفظ
الإصداري، ومنع تعديل التاريخ، وكشف تعارض Autosave. يجب الاعتماد على GitHub Actions
الخاص بفرع Cloud Foundation للحصول على العدد والنتيجة النهائية قبل الدمج.

لم يُنفذ فحص بصري داخل متصفح ضمن اعتماد الأساس الأصلي. أي دمج لـCloud Foundation
يجب أن يستهدف `codex/preserve-theme-cloudflare` فقط، لا `main`.
